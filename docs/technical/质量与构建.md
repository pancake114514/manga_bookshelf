## 5. CI（`.github/workflows/ci.yml`）

| 项 | 值 |
| --- | --- |
| 触发 | `push` 到 `master`/`tauri` 分支；任意 `pull_request`（`ci.yml:3-6`） |
| 运行器 | `windows-latest`（单平台，无矩阵） |

步骤顺序为：checkout → rust 工具链 → rust 缓存 → setup-node → **前端构建** → clippy → cargo test → cargo build。

注意：CI 只做 `cargo build`（debug），**不产出安装包**；打包只在 Release 工作流发生。

## 7. 本地开发

### 7.1 前置

```bash
cd frontend && npm ci && cd ..     # 有 package-lock.json，用 ci 而非 install
node dev.mjs                        # 推荐：随机端口启动器
```

Rust stable ≥ `1.77`（`Cargo.toml:7` `rust-version`）、Node ≥ 20（与 CI 一致）。

### 7.2 端口协商机制（`dev.mjs`）

| 环节 | 行为 | 行号 |
| --- | --- | --- |
| 选端口 | 在 `20000–60000` 间 `randomInt`，用 `net` 在 `127.0.0.1` 试绑验证空闲，最多 50 次 | `19-39` |
| 注入前端 | 环境变量 `MANGASHELF_DEV_PORT` → `vite.config.js` 的 `server.port` | `59`；`vite.config.js:12` |
| 注入 Tauri | 写临时 config `{build:{devUrl}}` 到系统临时目录，用 `tauri dev --config` 传入 | `49-57` |
| Windows 处理 | `.cmd` 必须 `shell: true`；因此配置走**文件**而非内联 JSON（否则 cmd 剥掉双引号） | `44-47,49-51,60` |
| 清理 | 子进程退出时删除临时配置并透传退出码 | `66-68` |

`strictPort: true`（`vite.config.js:13`）是必需项：端口被占时必须立刻失败，否则 vite 自行换端口、Tauri 仍指向旧 `devUrl`，窗口会加载到错误地址或空白。

### 7.3 必须在仓库根运行 tauri

`tauri.conf.json` 位于 `src-tauri/`，其中 `frontendDist: "../frontend/dist"`、`beforeDevCommand.cwd: "../frontend"` 均按「配置相对自身」解析；而 `dev.mjs` 以 `process.cwd()` 为基准 spawn `frontend/node_modules/.bin/tauri`。两者都要求 cwd = 仓库根（README:97 的约束由此而来）。

| 方式 | 命令 | 端口 | IPC |
| --- | --- | --- | --- |
| 随机端口（推荐） | `node dev.mjs` | 20000–60000 随机 | 可用 |
| 固定端口 | `./frontend/node_modules/.bin/tauri dev`（Windows：`frontend\node_modules\.bin\tauri.cmd`） | 5173 回退 | 可用 |
| 仅前端 | `cd frontend && npm run dev` | 5173 | **不可用**（见 §10） |
| 根 package.json 快捷方式 | `npm run dev` / `npm run build`（直接调 `frontend/node_modules/@tauri-apps/cli/tauri.js`） | 5173 回退 | 可用 |

`package.json:1-8`（仓库根）当前是**未跟踪**文件，属用户本地便利脚本，不在版本库内，不应写进构建文档的强制路径。

## 9. 既有约定与禁区

| 约定 | 内容 | 依据 |

## 10. 验证边界（务必先读）

| 场景 | 能验证什么 | 不能验证什么 |
