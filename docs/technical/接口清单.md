# 接口清单

覆盖 24 个 Tauri command 与自定义协议 `mangashelf://`。**请求/响应字段名以 commands.rs 的 serde 结构体为准**，
不要按前端 camelCase 猜测。

命名规则（重要）：

| 层级 | 规则 | 证据 |
| --- | --- | --- |
| 命令名 | 等于 Rust 函数名（snake_case），宏用 `stringify!(#command)` | lib.rs:134-159 |
| 顶层参数名 | Tauri 宏默认按 **camelCase** 改写 Rust 参数名，因此 JS 侧写 `includeR18`/`deleteFiles`/`sid` 等 | [api.js](../../frontend/src/api.js):17-26 与 commands.rs:350-355、531-535（外部依赖 tauri-macros 2.6.3 的 `ArgumentCase::Camel` 默认值） |
| 嵌套结构体字段 | 不做改写，**严格 snake_case**（`source_dir`、`is_new`、`obj_id`、`new_root`、`page_idx`、`cover_image`、`series_name`） | api.js:34-35 + commands.rs:22-86 |
| 出错 | 绝大多数是 `Err(String)`（JS 侧 reject，值是字符串）；少数"业务失败"返回 `Ok({ok:false,error})` | 见第 5 节 |

## 3. 自定义协议 `mangashelf://`

注册位置：lib.rs:88-133（`register_asynchronous_uri_scheme_protocol("mangashelf", …)`）。
图片、缩略图、封面**都不走 IPC**，由 WebView 直接发起协议请求；IPC 只返回 URL 字符串。

### 3.1 URL 规范

| 平台 | URL 前缀 | 说明 |
| --- | --- | --- |
| Windows（WebView2） | `http://mangashelf.localhost/` | wry 把 `http://mangashelf.localhost/x` 还原成 `mangashelf://localhost/x` 交给 handler（lib.rs:89-91） |
| macOS / Linux | `mangashelf://localhost/` | 直接使用 scheme |

三类资源（路径部分恒为 `/object/{oid}/…`）：

| 资源 | 路径 | 解析动作 | 缩略图 | 依据 |
| --- | --- | --- | --- | --- |
| 封面 | `/object/{oid}/cover?v={ver}` | `get_object` → `resolve_cover`（显式封面 → 首图 → 查库，均要求文件存在） | 文件名小写以 `.thumb` 开头 → **直出原图**；否则按 `COVER_THUMB_SIZE (180,240)` 生成 | commands.rs:657-675 |
| 网格缩略图 | `/object/{oid}/thumb/{imgid}` | `get_image_by_id(oid,imgid)` | `GRID_THUMB_SIZE (160,160)` | commands.rs:676-689 |
| 原图 | `/object/{oid}/image/{imgid}` | `get_image_by_id` | 不生成，直接读文件 | commands.rs:687 |

### 3.2 解析规则（commands.rs:638-692）

1. 先按 `?` / `#` 截断查询串与片段（否则 `cover?v=xxx` 会被当作 kind）。
2. 找第一个 `"/object/"`，取其后的子串并去掉前导 `/`；找不到 → Err「无效的 URL: 缺少 /object/ 路径」。
3. `split('/')` 后不足 3 段 → Err「URL 路径不完整」。
4. `parts[1]` = oid，`parts[2]` = kind，`parts[3]` = imgid（`thumb`/`image` 必需，缺失 → Err「缺少图片 ID」）。
5. kind 不属于 `cover`/`thumb`/`image` → Err「未知的图片类型: …」。
6. 任何 Err 在协议层都转成 **404**，响应体是错误字符串（lib.rs:123-129）。

### 3.3 缩略图 kind 推导

- 协议层拿到 `Option<(w,h)>` 后拼 `kind = "{w}_{h}"`（lib.rs:106），再由 `parse_thumb_kind` 拆回尺寸（commands.rs:695-703）。
- 也就是 kind 由**本进程内的尺寸常量**生成，外部 URL 无法指定尺寸；解析失败的回退值 `THUMBNAIL_SIZE (220,300)` 仅在手工构造 URL 时可达。
- 尺寸常量：`THUMBNAIL_SIZE (220,300)`、`GRID_THUMB_SIZE (160,160)`、`COVER_THUMB_SIZE (180,240)`（config.rs:7-9）。

### 3.4 并发与缓存策略

| 环节 | 策略 | 依据 |
| --- | --- | --- |
| 线程模型 | **每请求一条 OS 线程**（无池化）；避免同步 handler 堵死 WebView2 主线程 | lib.rs:94-98 |
| 缓存探测 | 先无锁查缓存命中，命中直接读文件、不占并发许可 | lib.rs:103-110 |
| 生成限流 | 未命中才 `acquire()` 计数信号量（许可数 **2**），完成后 `release()` | lib.rs:22、105-118 |
| 生成失败 | `get_thumbnail_path` 返回 Err → **回退发原图**（保证不出现破图） | lib.rs:113-115 |
| 缓存键 | `sha256("v2:" + 源路径 + 尺寸)[..16]` + `__mtime_ns_len`；源图替换即失效 | thumbnail.rs:22-49 |
| HTTP 缓存 | 成功响应带 `Cache-Control: max-age=3600` | lib.rs:219 |
| 封面防旧图 | 封面 URL 带 `?v=`（`sha256(cover\|first_image)[..6]` 的 12 位 hex），封面路径变化即换 URL | commands.rs:265-275 |

### 3.5 响应形态

| 场景 | 状态码 | 头 | 体 |
| --- | --- | --- | --- |
| 命中文件 | 200 | `Content-Type: <MIME>`、`Cache-Control: max-age=3600` | 文件字节（整文件读入内存） |
| 文件不存在 | 404 | — | `File not found` |
| URL 解析失败 | 404 | — | 错误字符串（如「对象不存在」「无封面」） |

MIME 仅按扩展名判断：jpeg/png/webp/gif/bmp/tiff，其余 `application/octet-stream`（lib.rs:230-247）。

## 5. 错误形态与接口差异

### 5.1 Err(String) vs Ok({ok:false})

| 形态 | 命令 | 前端处理 |
| --- | --- | --- |
| **业务失败用 `Ok({ok:false,error})`** | setup、validate_name | 必须判 `res.ok`（SetupGate/ImportDialog 已按此处理） |
| 成功恒 `ok:true` 的包装 | update_object、set_last_read、remove_bookmark、set_config_value、delete_object、import_*、migrate、prune_thumb_cache | 失败一律走 reject |
| **一律 Err(String)** | 其余查询类命令 | reject 的值是**字符串**，不是 Error 对象：前端惯用 `e.message \|\| String(e)` |
