# 数据模型

单文件 SQLite（rusqlite bundled），WAL 模式，连接级 `PRAGMA foreign_keys = ON`（db.rs:201）。
结构版本由 `PRAGMA user_version` 表示，当前为 **3**；`config.schema_version` 只是兼容旧版的遗留记录，**没有代码读取它**（db.rs:161-162）。
模块实现细节见 [架构与模块](架构与模块.md)，命令与 URL 的完整规则见 [接口清单](接口清单.md)。

## 1. 完整 DDL

三种来源：基线（全新库一次性建表）、v2/v3 增量（老库补列补表）。定义在 db.rs:108-190。

### 1.1 v1 基线（db.rs:108-163，`BASELINE_DDL`）

仅在 `user_version = 0` **且 `objects` 表不存在**时执行。

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS config (
    key   TEXT PRIMARY KEY,
    value TEXT
);

CREATE TABLE IF NOT EXISTS objects (
    id            TEXT PRIMARY KEY,
    type          TEXT NOT NULL CHECK(type IN ('directory','file')),
    name          TEXT NOT NULL,
    source_path   TEXT,
    storage_path  TEXT,
    cover_image   TEXT,
    last_read_idx INTEGER DEFAULT 0,
    created_at    DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS tags (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    object_id TEXT NOT NULL,
    category  TEXT NOT NULL,
    value     TEXT NOT NULL,
    FOREIGN KEY (object_id) REFERENCES objects(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS images (
    id         TEXT PRIMARY KEY,
    object_id  TEXT NOT NULL,
    filename   TEXT NOT NULL,
    filepath   TEXT NOT NULL,
    sort_order INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (object_id) REFERENCES objects(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_tags_object          ON tags(object_id);
CREATE INDEX IF NOT EXISTS idx_images_object        ON images(object_id);
CREATE INDEX IF NOT EXISTS idx_tags_category_value  ON tags(category, value);
CREATE INDEX IF NOT EXISTS idx_objects_created      ON objects(created_at DESC);

-- 去历史重复标签后建唯一约束
DELETE FROM tags WHERE id NOT IN (
    SELECT MIN(id) FROM tags GROUP BY object_id, category, value
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_tags_unique
    ON tags(object_id, category, value);

-- 清理历史孤儿
DELETE FROM tags   WHERE object_id NOT IN (SELECT id FROM objects);
DELETE FROM images WHERE object_id NOT IN (SELECT id FROM objects);

-- 兼容旧版 config 记录
INSERT OR IGNORE INTO config(key, value) VALUES('schema_version', '1');
```

```sql
CREATE TABLE IF NOT EXISTS bookmarks (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    object_id  TEXT NOT NULL REFERENCES objects(id) ON DELETE CASCADE,

```

### 1.4 执行模型（db.rs:217-264）

| 规则 | 说明 | 行号 |
| --- | --- | --- |
| 版本探测 | 先读 `PRAGMA user_version` | 218-220 |
| 分支判定 | `=0` 时查 `sqlite_master` 是否已有 `objects` 表 | 222-230 |
| 原子性 | 每一版 DDL 与 `PRAGMA user_version = N` 写在**同一事务**（`unchecked_transaction`），消除"DDL 已提交而版本没更新"的崩溃窗口 | 235-246、249-261 |
| 顺序 | 基线 → 2 → 3，只执行 `current < target` 的步骤 | 249-261 |
| 无降级 | `user_version > 3` 不报错、不处理（前向兼容未实现） | 249 |

失败语义：任一步 `execute_batch` 失败 → 事务未提交、返回 `Err("迁移至 vN 失败: …")`，`Database::open` 随之上抛，lib.rs:67-73 打日志并 `panic!`。

### 2.3 tags（行式标签）

| 字段 | 类型/约束 | 语义 |
| --- | --- | --- |
| id | INTEGER PK AUTOINCREMENT | 仅作排序与去重锚点（`ORDER BY id` 保留写入顺序） |
| object_id | TEXT NOT NULL，FK → objects(id) ON DELETE CASCADE | 归属对象 |
| category | TEXT NOT NULL | 类别，**无 CHECK**，任意字符串可写入 |
| value | TEXT NOT NULL | 值文本；r18 存 `"true"`/`"false"`，其余存原始值（rating 存 `"1"`…`"5"`） |

唯一索引 `(object_id, category, value)` 保证同对象同类别同值只一行（db.rs:154-155）。

### 2.4 images

| 字段 | 类型/约束 | 语义 |
| --- | --- | --- |
| id | TEXT PK | UUID，用于 URL `/image/{imgid}` |
| object_id | TEXT NOT NULL，FK → objects(id) ON DELETE CASCADE | 归属对象 |
| filename | TEXT NOT NULL | 磁盘文件名（可能含 `(1)` 去重后缀，不含目录） |
| filepath | TEXT NOT NULL | 绝对路径，协议层直接读它 |
| sort_order | INTEGER DEFAULT 0 | 页序（0 基，**允许空洞**，无唯一约束） |
| created_at | DATETIME DEFAULT CURRENT_TIMESTAMP | — |

页序读取一律 `ORDER BY sort_order, filename`（db.rs:859），因此 `sort_order` 相同（或历史空洞）时按文件名兜底，排序仍确定。

### 2.5 series

| 字段 | 类型/约束 | 语义 |
| --- | --- | --- |
| id | TEXT PK | UUID |
| name | TEXT NOT NULL UNIQUE | 系列名，**唯一性由 DB 保证**；按名 `get_or_create` |
| created_at | DATETIME DEFAULT CURRENT_TIMESTAMP | — |

系列不存成员数：`list_series` 现算 `COUNT(o.id)`，并用相关子查询取 volume 最小（NULLS LAST）成员的 `cover_image` 作为 `first_cover`（db.rs:699-726）。

### 2.6 bookmarks

| 字段 | 类型/约束 | 语义 |
| --- | --- | --- |
| id | INTEGER PK AUTOINCREMENT | 删除接口按它定位 |
| object_id | TEXT NOT NULL，FK → objects(id) ON DELETE CASCADE | 归属对象 |
| page_idx | INTEGER NOT NULL | 页索引，与 `last_read_idx`、`images` 位置同坐标系（0 基） |
| note | TEXT | 备注，可为 NULL |
| created_at | DATETIME DEFAULT CURRENT_TIMESTAMP | — |

`UNIQUE(object_id, page_idx)` 支撑 `INSERT … ON CONFLICT DO UPDATE SET note=excluded.note` 的幂等 upsert（db.rs:943-964）。

## 4. 外键与 CASCADE 影响面

| 触发操作 | 数据库行为 | 影响面 | 依据 |
| --- | --- | --- | --- |
| `DELETE FROM objects WHERE id=?` | tags / images / bookmarks 三表对应行 **CASCADE 删除** | 标签、页记录、书签、阅读进度（在 objects 行内）一并消失；文件与缩略图缓存**不会**被 DB 删除，由 `service::delete_object` 另行处理 | db.rs:132、142、183；service.rs:558-615 |
| `DELETE FROM series WHERE id=?` | `objects.series_id` **SET NULL** | 成员对象退回"未归类" | db.rs:175 |
| 更新 `objects.id` | 无 UPDATE CASCADE，子表不会跟随（代码从不改主键） | — | 同上 |

补充事实：

1. 级联只在该连接 `PRAGMA foreign_keys = ON` 时生效；连接建立时设置（db.rs:201）。
2. 基线 DDL 里那句 `PRAGMA foreign_keys = ON` 处于事务内，SQLite 规定事务内该 PRAGMA 为 no-op——外键实际由第 1 条保证。
3. `prune_empty_series` 只删除"零对象引用"的系列（db.rs:429-439），所以 SET NULL 分支在现有代码路径中**不会被触发**，它只是 schema 层的兜底。
4. 删除对象时若物理删除失败或被跳过，DB 记录已删、文件残留——`warnings` 透出给前端，不回滚（service.rs:593-615）。

## 5. 标签模型：Bool | List 的 serde 设计

数据库里是"行式"（每值一行），内存与 JSON 里是"类别 → 值集合"的映射，二者的桥是 `Tags`：

```rust
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
#[serde(transparent)]
pub struct Tags(pub HashMap<String, TagValue>);

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(untagged)]
pub enum TagValue {
    Bool(bool),
    List(Vec<String>),
}
```

（db.rs:80-90）

| 方向 | 规则 | 依据 |
| --- | --- | --- |
| DB → 内存 | `category == "r18"` → `Bool(value == "true")`；其余累积为 `List`（保持 `ORDER BY id` 顺序） | db.rs:745-765 |
| 内存 → DB | `Bool(b)` → 单行 `b.to_string()`（`"true"`/`"false"`）；`List` → 每值一行并**跳过空串**；先保序去重 | db.rs:768-787 |
| 内存 → JSON | `Bool` → JSON 布尔；`List` → 字符串数组 | commands.rs:191-207 |
| JSON → 内存 | `r18` **强制**按布尔解析，非布尔一律 `false`；数组只保留字符串元素（数字被丢弃）；单个字符串 → 单元素数组 | commands.rs:209-227 |
| r18 判定 | `Tags::is_r18()` 只认 `Bool(true)`；`include_r18=false` 时在装配阶段过滤 | db.rs:92-102、534-537 |

因此：

- `r18` 只有两种可写形态：`true` / `false`（前端 EditDialog 直接传布尔）。
- 其余类别都是字符串数组；`rating` 存 `["3"]` 这种形态，**传数字数组（`[3]`）会被静默丢弃**。
- 类别集合无 schema 约束。代码里的"已知类别"是 `config::tag_category_order()`：`work, author, character, cm, censored, r18`（config.rs:16-18）——**不含 rating**；`get_tag_values` 命令又跳过 r18，所以前端只能拿到 5 类候选值（commands.rs:431-443）。
- `rating` 由前端单独处理：筛选语义是"n 星及以上"，实现为把 `[n..5]` 全放进 `filters.rating`（frontend/src/components/TagSidebar.vue:80-94）。

## 6. 存储布局与路径规范

### 6.1 目录树

```
<DB>                      Windows: %APPDATA%\MangaShelf\library.db
                          Linux/macOS: ~/.local/share/MangaShelf/library.db
                          （环境变量 MANGASHELF_DB 可覆盖）        config.rs:25-43
<DB>.bak                  迁移前的库备份（成功后删除）            library_manager.rs:212-217、321

<storage_root>/                                     config["storage_root"]
├── <对象名>/                     ← objects.storage_path（绝对路径）
│   ├── 0001.jpg                  ← images.filepath；filename 同名
│   ├── 0001(1).jpg               ← 同名冲突时的 (n) 去重
│   └── .thumb.jpg                ← 封面缩略图，.thumb 开头不参与正文
└── .thumbcache/                  ← THUMB_CACHE_DIR（config.rs:11）
    ├── <hash32>__<mtime_ns>_<len>.jpg       ← 缩略图
    └── <hash32>__<mtime_ns>_<len>.jpg.tmp   ← 生成中的临时文件
```

要点：

- 目录名 = 对象名，不做额外哈希/转义；同名由"存储目录已被其他对象占用"检查拦住（service.rs:687-690）。
- `.thumb*` 封面文件被复制进对象目录并记为 `cover_image`；`collect_images` 过滤 `.` 开头，故不会混入正文（file_ops.rs:51、service.rs:734-745）。
- 旧根的 `.thumbcache` 在迁移成功后整体删除（library_manager.rs:315-318）。
- 缩略图文件名规则（含生成器版本 `v2` 与 mtime/size）见 [架构与模块](架构与模块.md) 第 7.1 节。

### 6.2 路径字段与比较规范

| 规则 | 实现 | 依据 |
| --- | --- | --- |
| DB 中一律存**绝对路径** | 导入时 `Path::new(storage_root).join(..)`；`images.filepath` 取复制目标全路径 | service.rs:687、759-761 |
| 路径归一化 | `normalize_path`：先 `canonicalize`（失败保留原串），Windows 下 `to_lowercase` | library_manager.rs:46-54 |
| 包含判定 | `is_relative_to` 用 `strip_prefix` 且要求剩余非空（组件级），避免 `D:\Manga2` 被当作 `D:\Manga` 的子目录 | library_manager.rs:56-64 |
| 目录占用判定 | `storage_path_taken` 对两侧都做 `normalize_path` 后比较；**调用方必须已持 DB 锁** | service.rs:524-553 |
| 唯一例外 | `map_path`（迁移重写路径）仍用字符串 `starts_with` | library_manager.rs:66-77（见差异清单） |

## 7. 图片 URL 与封面缓存版本参数

| 资源 | URL 形态（Windows） | 缩略图尺寸 | 是否带版本参数 |
| --- | --- | --- | --- |
| 封面 | `http://mangashelf.localhost/object/{oid}/cover?v={ver}` | `COVER_THUMB_SIZE (180,240)`；源为 `.thumb*` 时直出原图 | **是**：`v` = `sha256(cover_image + "\|" + first_image)[..6]` 的 12 位 hex |
| 网格缩略图 | `http://mangashelf.localhost/object/{oid}/thumb/{imgid}` | `GRID_THUMB_SIZE (160,160)` | 否 |
| 原图 | `http://mangashelf.localhost/object/{oid}/image/{imgid}` | 不生成缩略图 | 否 |

- macOS/Linux 前缀为 `mangashelf://localhost/`（commands.rs:306-315）。
- 封面必须带版本参数：WebView 对同 URL 复用缓存，换封面后路径变而 URL 不变会继续显示旧图；`cover_image` 与回退首图**都**参与哈希，所以"设封面"和"封面失效回退首图"都会换 URL（commands.rs:265-275，测试 817-824）。
- 缩略图/原图不带 `?v=`：URL 由不可变的 `imgid` 构成，缓存新鲜度靠缩略图文件名里的 mtime+size 与 HTTP `Cache-Control: max-age=3600`。
- 协议解析细节（剥离 query、`/object/` 定位、kind 分类）见 [接口清单](接口清单.md) 第 3 节。

## 8. 迁移对老库的兼容路径（`user_version = 0` 的两种情况）

| 场景 | `user_version` | `objects` 表 | 实际执行 | 结果 |
| --- | --- | --- | --- | --- |
| 全新库 | 0 | 无 | 基线 DDL → 置 1 → v2 → v3 | 3，表/索引/去重/清孤儿齐全 |
| Python 版老库、早期 Rust 库 | 0 | **有** | 只执行 `PRAGMA user_version = 1` → v2 → v3 | 3，但**基线 DDL 整段被跳过** |
| 已升到 v1 | 1 | 有 | v2 → v3 | 3 |
| 已升到 v2 | 2 | 有 | v3 | 3 |
| 已是 v3 | 3 | 有 | 无操作（幂等，测试 1180-1196） | 3 |
| 版本 > 3 | >3 | — | 无操作、不报错 | 保持 |

老库路径的**具体缺口**（基线 DDL 不执行导致的后果）：

| 缺失项 | 后果 |
| --- | --- |
| `idx_tags_unique` | 同一对象同类别同值可重复插入；`set_tags` 自己会去重，但历史重复行不会被清理 |
| `idx_tags_category_value` / `idx_objects_created` | 标签值聚合与按 `created_at` 排序退化为全表扫描（功能不受影响） |
| 两条清孤儿 `DELETE` | 历史孤儿 tags/images 行残留；`get_all_image_filepaths` 会把它们带进缩略图 keep 集合 |
| `config('schema_version','1')` | 该键缺失；无代码读取，无实际影响 |

> ⚠ 与文档差异（2026-11-10 已对齐）：[README](../../README.md) 第 82-83 行原称"老库启动时自动增量升级"，
> 现已补充"只执行增量步骤、不重跑基线 DDL，基线唯一索引可能缺失"。
> 代码确实能让老库打开并补出 `series`/`bookmarks`，但**不等于补齐基线约束**；
> [handoff](../../handoff.md) 第 5 节 2.5 的"新增幂等增量步骤补唯一索引"仍是待办，本次未实现。

## 9. 应用层约束（数据库没有约束的部分）

| 约束 | 实现方式 | 风险 |
| --- | --- | --- |
| 一个 `storage_path` 只属于一个对象 | `service::storage_path_taken` 在插入/重建前检查（含 `normalize_path`） | 检查与写入不在同一事务，理论上有竞态 |
| 同系列 `volume` 不重复 | `service::set_series_for_object` 先 `find_series_volume_conflict` 再写 | 无 DB 唯一约束；并发写可绕过 |
| `sort_order` 单调追加 | `db::next_sort_order = MAX+1` | 无唯一约束；并发追加可能撞号 |
| `cover_image` 指向存在的文件 | 不校验；读时 `resolve_cover` 三级回退（封面 → 首图 → 查库） | 记录可以是失效路径 |
| 系列名唯一 | `series.name UNIQUE` | DB 保证 |
| 空系列自动回收 | `prune_empty_series`，在系列引用变化后调用 | 幂等，但只有调用点才生效 |
| 对象与目录一对一 | 目录名取对象名；删除时共享目录跳过物理删除 | 历史数据可能存在共享目录（代码已防御） |

## 10. 已知数据缺口

1. 无软删除、无审计表：删对象即物理删行 + 级联。
2. 无"页面内容哈希"：同一图片重复导入到同一对象会生成多条 `images` 行（仅按文件名去重）。
3. 书签与阅读进度都基于**位置索引**，`sort_order` 一旦重排即全体错位；[handoff](../../handoff.md) 第 4 节明确"不重排存量 sort_order"。
4. `objects.type` 的 `'file'` 分支没有任何写入路径（预留）。
