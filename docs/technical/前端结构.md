### 1.2 启动链

`App.vue:79` onMounted → `boot()`（`store.js:56-93`）：

1. `store.bootError = null`；`store.ready = false`（重试时回到加载态，避免沿用上一轮 ready 渲染空书架）。
2. `api.state()` → `store.storageRoot = st.valid ? st.storage_root : null`（后端同时校验目录存在与可写，`commands.rs:320-330`）。
3. 并行读 9 个 config 键（`store.js:62-67`），逐项白名单校验后写入 store。
4. `storageRoot` 存在时再拉 `api.tagValues()` 与 `api.series()`（`store.js:84-87`）。
5. 任一步抛错 → `store.bootError = e.message`；`finally` 置 `ready = true`（`store.js:88-92`）。

## 2. App.vue：渲染优先级与视图三分支

### 2.1 渲染优先级（严格自上而下）

| 优先级 | 条件 | 渲染内容 | 行号 |
| --- | --- | --- | --- |
| 1 | `store.bootError` | `n-result` 启动失败面板 + 「重试」→ `boot()` | `App.vue:11-17,78` |
| 2 | `store.ready === false` | 全屏 `n-spin` 加载态 | `App.vue:33` |
| 3 | `ready && !store.storageRoot` | `SetupGate`（首启选库目录） | `App.vue:19` |
| 4 | `ready && storageRoot` | 主界面（顶栏 + 侧栏 + 视图 + 两个对话框） | `App.vue:20-31` |

`bootError` 必须先于 `ready` 判断：旧实现 `finally` 无条件 `ready=true` 会渲染 SetupGate，把启动失败伪装成「请先设置目录」（handoff §2.1 P1 项的成因）。

### 2.2 视图三分支

`store.view = { name: 'shelf' | 'directory' | 'reader' }`（`store.js:44`）。

| 视图 | 主组件 | 左侧栏 | TopBar | 依据 |
| --- | --- | --- | --- | --- |
| `shelf` | `Bookshelf` | `TagSidebar`（筛选） | 显示 | `App.vue:21,23,25` |
| `directory` | `DirectoryView` | `DirectorySidebar`（分卷/书签） | 显示 | `App.vue:24,26` |
| `reader` | `Reader` | 无 | **隐藏**（Reader 自带 58px 顶栏） | `App.vue:21,27` |

`showSidebar = view.name === 'shelf'`（`App.vue:66`）；`showTitleBar = !ready || !storageRoot`（`App.vue:67`）——只有首启/异常态才有独立 38px 窗口条（`TitleBar.vue:15-20`）。
`ImportDialog` / `LibraryDialog` 挂在主界面层，导入完成 `store.reloadTick++` 让书架静默刷新（`App.vue:29-30`）。

### 2.3 设计令牌注入与 Ctrl+B

- `watchEffect` 把 `cssVars(store.theme)` 逐个 `setProperty` 到 `document.documentElement`（`App.vue:60-63`）。原因：Naive UI 的 dropdown/popover 会 teleport 到 body，只绑在 `.app-shell` 上的 `--ms-*` 在弹层里取不到值。
- Ctrl/Cmd+B 只对 `shelf`/`directory` 生效，输入框/可编辑元素内不劫持（`App.vue:70-76`）。

2. `getConfig` 在封装层就 `.then(r => r.value)` 解包（`api.js:53`），调用方拿到的是字符串或 null。**调用方再取 `.value` 会恒 undefined**（handoff §2.1 P2 项的成因，已在 `Reader.vue:446-449` 修正）。

## 6. sidebar.js：拖动 / 吸附 / 持久化时机

几何常量收敛在 `constants.js:19-22`（单一真源，store 校验与拖动共用）：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `SIDEBAR_RAIL` | 28 | 收起后细条宽 |
| `SIDEBAR_MIN` / `SIDEBAR_MAX` | 180 / 400 | 展开态宽度上下限 |
| `SIDEBAR_SNAP` | 110 | 拖到此宽度以下松手 → 吸附为收起态 |

拖动状态机（`sidebar.js:20-44`）：

1. `pointerdown` 只认左键；记录 `startX` 与 `startW = sidebarWidth(view)`（收起时基准是 28，因此从细条向右拖可直接拖出恢复）。
2. 置 `store.sidebarDragging = view` → `.app-shell.sidebar-dragging` 全局禁用宽度过渡（`styles.css:31-32`）。
3. `pointermove`：钳制到 `[RAIL, MAX]`；`< SNAP` 只切 `ui.sidebar[view] = true`（预览收起），否则置 false 并把宽度 `max(MIN, w)` 写内存。
4. `pointerup`：解绑监听 → `sidebarDragging = null` → **此时才** `setSidebarCollapsed` 落库；仅展开态再 `setSidebarWidth` 落库。

即「拖动中只改内存，松手才写 config」，避免拖动期间高频写库。
有效宽度由 `sidebarWidth()` 统一给出（收起 → 28），组件只绑定行内 `style="width" `（`TagSidebar.vue:3`、`DirectorySidebar.vue:5`）。三通道入口：收起钮、分隔条拖动、双击分隔条、Ctrl+B（`TagSidebar.vue:6,51-57`）。

## 8. naming.js：命名解析规则与边界

输入格式：`[数字编号-](CM号)[作者名] 本名`，各段均可缺省；尾部 `[Chinese] [汉化组]` 留在本名内（`naming.js:1-4`）。

| 步骤 | 正则 / 规则 | 结果字段 | 行号 |
| --- | --- | --- | --- |
| ① 编号前缀 | `/^(\d+)\s*-\s*/`（半角数字 + `-`） | 剥掉后即为 `full`（对象名用） | `19-21` |
| ② CM 号 | `/^[（(]([^()（）]+)[）)]\s*/` 且内容**非纯数字** | `cm` | `27-31` |
| ③ 作者 | `/^[\[［]([^\[\]［］]+)[\]］]\s*/` | `author` | `36-40` |
| ④ 本名 | 剩余部分 | `name` | `43` |

边界（均有单测覆盖，`frontend/test/naming.test.mjs`）：

| 输入 | 结果 | 原因 |
| --- | --- | --- |
| `1762328-(COMIC1☆17) [OrangeMaru (YD)] Nightmare (FateGrand Order) [Chinese]...` | `full` 去掉编号；`cm=COMIC1☆17`；`author=OrangeMaru (YD)` | 完整格式 |
| `[作者乙] 本名 (2)` | `cm=null` | 圆括号**不在开头**，且纯数字不算 CM（避免把 `(2)` 当 CM） |
| `（C105）[角砂糖 (よろず)] …` | `cm=C105`、`author=角砂糖 (よろず)` | 全角圆括号/方括号兼容 |
| `999888-[作者甲] 只有本名` | `cm=null` | CM 段可缺省 |
| `随便一个文件夹名` / `''` / `null` | `full`=`name`=原值（空/空串），`cm=author=null` | 不匹配即原样保留 + 空值防御 |

`applyParsedTags(tags, parsed)`（`naming.js:52-57`）只填充**空**类别，不覆盖用户已填值——这是「解析是建议、不是命令」的边界。
调用点：`ImportDialog.vue:200-209`（新建目录时预填对象名与 cm/author 标签）、`ImportDialog.vue:245-254`（批量清单逐项预填对象名，勾选态取决于图片数）、`ImportDialog.vue:261-273`（逐项标签 = 解析值 ∪ 统一标签）。

### 9.6 TagSidebar：「n 星及以上」的实现方式

评分作为独立的 `rating` 类目写进 tags（`rating: ["n"]`，字符串数组；不在可编辑的 `CATS` 五类内，只由星级组件写入），筛选是按值精确匹配的 `filters.rating` 数组。前端把「≥n」翻译成**枚举**而不是比较：

```
minRating        = vals.length ? 6 - vals.length : 0       // TagSidebar.vue:81-84
setRatingFilter(n) → filters.rating = ['n','n+1',...,'5']  // TagSidebar.vue:85-91
```

因为评分只可能是 1–5 的整数，取连续后缀即可与精确匹配语义等价；点亮星数由 `6 - 数组长度` 反推，点击当前星数再次即清除（`86`）。`RATING_CAT` 单一定义在 `constants.js:16`。
