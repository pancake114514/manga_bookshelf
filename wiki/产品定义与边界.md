# 产品定义与边界

> **事实源声明**：本文的产品定位与边界均由代码反推，代码是唯一事实源。凡与 README.md、handoff.md 冲突处一律以代码为准，并以「⚠ 与文档差异」标注。
> M1 的逐条验收口径见 [M1-Requirements](M1-Requirements.md)；名词定义见 [产品术语表](产品术语表.md)；技术事实源见 docs/technical/README.md（本轮并行任务产出，见文末 §7）。

## 1. 一句话定位

MangaShelf 是一个**纯本地的桌面漫画/图片库管理器**：把散落在磁盘上的图片目录导入到统一的图库根下登记、打标签、归系列，然后以书架/详情/阅读器三层界面浏览与阅读。**不联网、不登录、不上传，数据不出本机。**

## 2. 定位四要素

| 要素 | 事实 | 代码依据 |
| --- | --- | --- |
| 形态 | Tauri 2 桌面应用（无边框窗口，Win32/macOS/Linux 打包） | src-tauri/tauri.conf.json:18-34、src-tauri/src/lib.rs:75-209 |
| 技术形态 | Rust 后端 + Vue 3 WebView 前端；图片由自定义协议直供，不经 IPC | src-tauri/src/lib.rs:88-133、src-tauri/Cargo.toml:16-29 |
| 数据归属 | 全部数据在本机两处：SQLite 库文件 + 图库根目录内的图片文件 | src-tauri/src/config.rs:29-42、src-tauri/src/config.rs:11 |
| 用户模型 | 单用户、单实例、无账号、无权限、无多租户 | src-tauri/src/lib.rs:78-84（single-instance 插件） |

## 3. 数据不出本机（可验证口径）

| 检查项 | 结论 | 依据 |
| --- | --- | --- |
| 后端是否引入 HTTP 客户端 | 否。依赖表无 reqwest/ureq/hyper 等出站客户端 | src-tauri/Cargo.toml:16-29 |
| 前端是否发起网络请求 | 否。仅用 @tauri-apps/api 的 IPC 与 dialog 插件 | frontend/package.json:11-21、frontend/src/api.js:1-120 |
| 图片读取路径 | 自定义协议 mangashelf:// 由后端从本地磁盘读文件后回给 WebView | src-tauri/src/lib.rs:88-133、src-tauri/src/lib.rs:212-228 |
| 数据库位置 | Windows %APPDATA%/MangaShelf/library.db；其他平台 ~/.local/share/MangaShelf/library.db；可用环境变量 MANGASHELF_DB 覆盖 | src-tauri/src/config.rs:29-42 |
| 图片存储位置 | 用户自选图库根，对象目录为其直接子目录 | src-tauri/src/service.rs:687、src-tauri/src/library_manager.rs:42-44 |
| 遥测/崩溃上报/自动更新 | 未实现（代码中无对应模块） | 全仓检索无相关依赖 |
| 唯一外部交互 | 调系统资源管理器「在文件夹中显示」 | src-tauri/src/commands.rs:771-789 |

## 5. 明确边界（不做什么）

### 5.1 不做在线源 / 不做网络抓取

- 无漫画站解析、无下载器、无 URL 输入框；图片**只能**来自本地文件系统（目录或文件选择对话框）。
- 依据：frontend/src/api.js:97-119 只有 pickDir/pickDirs/pickFiles 三个本地选择器；src-tauri/src/commands.rs:550-598 的导入命令只接受本地路径。
- 推论：**没有**在线更新、订阅、爬虫、账号绑定等能力，未来若要加必须新增出站网络层（当前架构不具备）。

### 5.2 不做云同步 / 不做多端

- 无登录、无账号、无「同步」概念；跨机器搬运只能靠用户自行复制图库根 + 库文件。
- 库文件本身也不做云端版本管理：迁移备份是本机同目录的 .bak 文件（src-tauri/src/library_manager.rs:212-224）。

### 5.3 不允许绕过应用直接改数据库

两个层面都成立：

| 层面 | 约束 | 依据 |
| --- | --- | --- |
| 产品 | 所有数据变更只经「IPC 命令 → LibraryService → Database」单一路径；注册命令共 24 个，**没有**任意 SQL 执行入口 | src-tauri/src/lib.rs:134-159 |
| 产品 | 库文件是应用私有实现细节：schema 用 PRAGMA user_version 内部版本化，不承诺外部工具/外部版本兼容 | src-tauri/src/db.rs:217-264 |
| 项目约定 | 禁止 AI/开发者直接对本库执行 SQL、改数据或跑迁移脚本 | AGENTS.md §2 |

⚠ 与文档差异 / 风险：set_config_value 未做 key 白名单（src-tauri/src/commands.rs:622-629），理论上 IPC 调用方可直接改写 storage_root 从而绕过 setup 的目录可写校验与迁移流程。该风险来自 handoff.md:103（批次 4 P3），尚未修复。

### 5.4 单实例、单用户、无并发安全模型

- 二次启动唤起已有窗口后新进程退出（src-tauri/src/lib.rs:78-84），保证不会有两个进程同时写同一个 SQLite 库。
- 进程内并发由 Mutex<Connection> 串行化；数据库开 WAL（src-tauri/src/db.rs:201）但**没有**跨进程锁协议，因此「同时用外部工具打开库文件写」不在支持范围内。
- 无用户/角色/权限体系：谁能登录操作系统账号，谁就拥有全部数据。

### 5.5 附带边界（不承诺项）

| 不做/不承诺 | 说明 |
| --- | --- |
| 不支持压缩包（zip/rar/cbz） | SUPPORTED_FORMATS 只有 jpg/jpeg/png/bmp/webp/gif/tiff/tif：src-tauri/src/config.rs:3-5 |
| 不重排存量页序 | sort_order 一经写入不再全局重排，避免阅读进度与书签集体错位：handoff.md:73 |
| 不做目录名自适应改名 | 对象存储目录名由导入时的对象名决定，改名不改目录：src-tauri/src/service.rs:452-454 |
| 不保证库外路径自动跟随 | 手工指定的封面若在图库根之外，迁移后不更新该路径，只给 warning：src-tauri/src/library_manager.rs:231-245 |
